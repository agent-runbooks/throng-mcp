Security fix for `harness_mode: ask`. throng approves its own `submit_result` tool (structured output with `schema`) without consulting `permission_answers`, and it used to recognise that tool by two words in the permission request's title. On Claude, OpenCode and Gemini a shell command's permission request is titled with the command itself, on Copilot with a description the model writes, and on Codex the update announcing the command carries its text. So a command such as `echo throng_result submit_result; <anything>` was approved under `permission_answers: deny`, and under `elicit` you were never asked. Now only the exact form each harness gives throng's tool counts, and a request that carries a shell command never does; everything else goes to `permission_answers`, and a request that names `submit_result` without matching is logged as a warning in the server log. Structured output under `ask` keeps working on Claude, Codex, OpenCode, Cursor and Copilot. On Gemini CLI 0.62 and later the tool's request carries no server name, so under `ask` `permission_answers` decide for it: run Gemini with `harness_mode: auto` when you pass a `schema`. See [Permissions](https://github.com/agent-runbooks/throng-mcp/blob/main/docs/DESIGN.md#5-permissions) and [Harnesses](https://github.com/agent-runbooks/throng-mcp/blob/main/docs/harnesses.md).
